## How to update

Install the new build **over** the existing app. The in-app updater does exactly this — **Settings → Updates → Check for updates**, then Install — and it is the method to prefer.

<Danger title="Never uninstall first">
  Uninstalling deletes your playlists, liked tracks and listening history. Android removes application data on uninstall and it cannot be recovered.

  Your **downloads** survive either way; they are written to your own music folder, outside application storage.
</Danger>

See **[Updates](/reference/updates)** for how the check, the download and the installation work.

## Version numbering

The version is derived from the git tag by the build pipeline rather than written into a file, so the number shown under **Settings → App version** is always the tag the build came from. Tags take the form `vMAJOR.MINOR.PATCH`, and the app compares them numerically rather than as text, so `v1.0.10` is correctly newer than `v1.0.9`.

## Reporting a problem

**[Open an issue](https://github.com/subh-775/Music_Player/issues)** with:

- What you did, and what happened instead.
- Your Android version and device model.
- The contents of **Settings → Diagnostics** if the problem concerns playback or sound.

The last of those answers most questions on its own.
